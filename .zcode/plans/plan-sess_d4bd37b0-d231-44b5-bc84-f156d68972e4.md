# OneResi UI revamp — the plan

## Direction you locked (rounds 1–3)
Premium fintech · receipt ceremony as signature · alive & springy motion · gold+glow+glass token system · all four engagement mechanics (dues ring, on-time streak, society pulse, settled celebration) · hybrid desk (airy hero + dense tables) · witty-premium copy voice · theme follows system on first visit · generous pill-soft curves · bento composition · floating glass pill PWA nav · dual receipt (screen ritual + print-faithful A5). Whole-UI layout is in scope, and every phase ends with a real-browser visual test at phone + desktop, light + dark.

## Key facts the plan rides on
- Dark palette is complete in `packages/ui/src/tokens.css` but nothing sets it. `@theme inline` means one `data-theme` flip re-themes everything.
- `InvoiceView` has `dueOn`/`paidAt`/`receiptNo` per invoice; `GET /api/dashboard` returns collections/dues/previous/complaints/gate/bookings. Rings, streaks, pulse, and the settled trigger are all client-side derivable — no API or DB changes.
- Visitor name/purpose chips already exist on web + PWA; web already remembers payment method and last facility. Missing: complaint-category memory (both), PWA method + facility memory.
- `Money` already animates glyphs via framer-motion; `ProgressRing` exists (used only on register); `Table` has `rowTone`/`flashedRowKey`/keyboard nav but one fixed density; `Sheet` has drag-to-dismiss.
- E2E (`scripts/e2e-local.mjs`) is API-level; its only UI assertion is copy-gate-clean HTML on `/`. Gates: `check:copy`, `check:enums`.
- No custom fonts exist; the system stack ships. Deliberate call: keep it (rule: no new deps/assets) — identity comes from curves, gold/glass tokens, weight contrast, and motion.

6. Verify: both-app typecheck, lint, check:copy/enums.

## Standing rules
Tokens only (no hexes in pages) · copy gate · check:enums · no new deps · every interactive element keeps loading/empty/error · `prefers-reduced-motion` respected via existing `useMotion()` · dev consoles (`dev/sync`, `dev/cloud`) untouched · kiosk inherits token changes only · no `next build` alongside anything, no parallel vitest.
